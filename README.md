# SkinCar — сервер, этап 1

Подготовленная основа для Railway + PostgreSQL. Интерфейс остаётся на Netlify.
Сервис ещё не развёрнут. Существующий HTML пока не обращается к этому API.

Реализовано:
- проверка подписи Telegram initData на сервере, срок входа 10 минут;
- профиль пользователя, язык RU/KK/EN и тема в PostgreSQL;
- серверный баланс с начальным значением 0, клиент не может его изменить;
- сессия на 24 часа, в базе хранится только хеш токена;
- webhook /start с кнопкой https://skincar01.netlify.app/;
- health check с проверкой базы.

Демонстрационные 12 генераций из HTML не переводятся в реальный баланс.
ИИ, оплата, промокоды, хранение фотографий/проектов и баттлы в этот этап не входят.

## Развёртывание

1. Распакуй архив и загрузи все файлы этого комплекта в отдельный GitHub-репозиторий. Файл package.json должен быть в корне репозитория.
2. В Railway создай проект, добавь сервис из этого репозитория и PostgreSQL.
3. В Variables сервиса добавь:
   - BOT_TOKEN — токен именно @skincartuning_bot из BotFather. Только в Railway, не в HTML и не в репозиторий.
   - DATABASE_URL — reference на DATABASE_URL добавленного PostgreSQL.
   - WEBHOOK_SECRET — случайная строка из 64 шестнадцатеричных символов. Получить локально: node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
   - APP_URL — https://skincar01.netlify.app/
4. Команда запуска: npm start. Таблицы создаются автоматически. Один экземпляр сервиса на этом этапе. Node.js 22 или новее.
5. В настройках Networking создай публичный HTTPS-домен. Проверь /health: должен вернуть {"ok":true}.
6. Добавь PUBLIC_API_URL с полученным HTTPS-адресом и выполни в окружении сервиса: node setup-webhook.js. Это переключит webhook этого бота на новый сервер. Не выполняй, если старый обработчик бота ещё должен работать.
7. Отправь боту /start — он должен прислать кнопку открытия приложения.
8. Передай адрес сервера для подключения HTML. Токен бота передавать в чат не нужно.

## Подключение интерфейса следующим шагом

POST /api/auth/telegram с JSON {"initData": Telegram.WebApp.initData}.
Ответ: {session, user, expiresIn}. Хранить session в памяти приложения, не включать в URL и логи.
GET /api/me с Authorization: Bearer <session> возвращает профиль и баланс.
PATCH /api/me принимает только displayName, lang, theme. Баланс не принимается.
POST /api/logout отзывает текущую сессию.

Не заменять демонстрационные данные в HTML серверными частично: перед подключением отключить локальную покупку и списание генераций, отделить локальные демонстрационные проекты от реальных. API не доверяет балансу из localStorage.

## Проверки и ограничения

npm test — проверка валидного входа, подмены данных, неправильного бота, срока и дублирующихся полей.
Живые PostgreSQL, Railway и отправка сообщений требуют переменных окружения и проверяются после развёртывания.
До массового запуска нужны ограничение частоты запросов, контроль повторов webhook, резервные копии базы и мониторинг. Повторная доставка /start сейчас может дать повторное приветствие; денежных операций нет.
