# SkinCar SK-106 — Telegram-бот: функциональное ТЗ и статус реализации

**Версия:** SK-106 (22.11.2026). **База:** SK-105 Netlify без изменений; сервер GitHub/Railway на базе SK-101 (последний проверенный деплой до SK-106: `065bcf8`). **Статус:** код подготовлен локально, реальный Telegram и production PostgreSQL НЕ тестировались, НЕ развернуто.

## Что реализовано локально

1. **SK-009/010 — основное меню:** /start, /menu, кнопки «Мой гараж», «Открыть SkinCar», «Баланс», «Справка», «Поддержка», «Уведомления», «Покупки», «Статусы». RU/KZ/EN для ключевых текстов и FAQ. Только личные чаты.
2. **SK-095 — гараж:** /garage, список до 6 авто на страницу, переход к автомобилю, до 5 готовых образов на страницу, количество образов, последнее фото; список дополнительных исходных фото. Бот использует те же `vehicles`, `vehicle_photos`, `generations`, а не отдельную копию гаража.
3. **Фото:** preview = Telegram sendPhoto, скачивание = sendDocument multipart без пересжатия байтов из `result_image` либо `original_image`. До/После — два последовательных sendPhoto. Никакого обращения к OpenAI и списания генераций за выдачу.
4. **Удаление и приватность:** при каждом callback выполняется owner-bound JOIN и проверка `NOT archived` и `status='done'`. Удалённые авто/образы недоступны даже по старым кнопкам. Уже отправленные сообщения в Telegram не удаляются автоматически (это отдельные копии у Telegram).
5. **Профиль:** /balance, /purchases, /status. Покупки Stars только читаются. Коммерческий режим платежей не меняется.
6. **FAQ и обращения:** /faq [запрос], /help, /support (затем сообщение), /cancel, /mytickets. PostgreSQL-тикеты и /tickets, /reply <UUID> <текст>, /close <UUID> для операторов. Не присылать секреты и данные карты.
7. **Уведомления:** /notifications; пользователь явно включает/выключает уведомления. После завершения генерации событие ставится в PostgreSQL outbox; отдельный worker отправляет текст с кнопкой получения результата. Без разрешения пользователя уведомлений нет. Повторное нажатие проверяет актуальность образа.
8. **SK-011/012/013/071 — админка:** /admin, /stats, /stats_week, /stats_month, /models, /last, /cost, /limits, /botstatus. Только при `BOT_ADMIN_IDS` в Railway; в группах нет доступа. Счётчики, токены, Stars — без пользовательских фото. `USD` не рассчитываем без подтверждённой стоимости.
9. **SK-017 — баланс:** /credit <telegram_id> <1…100> <причина>, /debit <telegram_id> <1…100> <причина>. Оператор сначала создаёт заявку, затем подтверждает её отдельной кнопкой за 10 минут. Изменение атомарно, только один раз, с credit_ledger, долговыми корректировками и аудитом. Без подтверждения изменение баланса невозможно.
10. **SK-016 — промокоды:** /makepromo <1…20 генераций> <1…100 активаций> <1…30 дней>; пользователю /promo SC-... Код случайный 96-бит, в БД хранится только HMAC-хэш, каждому пользователю доступно не более одной активации каждого кода. Погашение долга учитывается.
11. **Защита:** секретный webhook, проверка from.id===private chat.id, все SQL параметризованы, владелец проверяется при каждом обращении, rate-limit updates и медиа, callback receipt-deduplication, уведомления с lease, лимит размера файлов и отсутствие секретов в журналах.
12. **Webhook:** регистрация включена даже если `PAYMENTS_MODE=off`, allowed_updates содержит `message`, `pre_checkout_query`, `callback_query`; существующие Stars payment/refund handlers сохранены. Исправлено повторное вызова settlePayment при refunded_payment.

## Чего SK-106 НЕ закрывает

- **SK-070/SK-014:** точную цену USD/прибыль: отсутствие полного каталога версионированных тарифов и фактических per-request затрат. Бот сообщает «данных недостаточно».
- **SK-015:** полное удалённое изменение любых серверных параметров через чат (чувствительные конфигурации по-прежнему только через Railway); реализовано только чтение состояния и управление собственными уведомлениями.
- **SK-018/019/020/036:** массовое включение Stars, вывод вознаграждений и финансовую сверку — требуют отдельного коммерческого и юридического QA.
- **SK-038/039:** массовые рассылки акций и баттлов. Только индивидуальное opt-in уведомление о готовом образе.
- **SK-041:** поддержку внутри пользовательского интерфейса Mini App (ботовая часть работает отдельно).
- **SK-042:** подключение большой редактируемой поисковой базы знаний (базовые ответы встроены, с поиском по словам).
- **SK-044:** вложения поддержки, SLA, расширенную очередь оператора.
- Реальную проверку Telegram Bot API, больших файлов, повторных вебхуков и удаления при одновременной выдаче в production PostgreSQL; байтовую проверку у реальных Telegram-клиентов и живые проверки RU/KK/EN.
- Реальный live-тест оплат Stars и фактическое уведомление клиента после генерации.


## Короткая инструкция

1. Сохранить резервную копию текущего main GitHub, желательно создать commit/tag.
2. В корень `skincar-server` добавить `bot-service.js`, `bot-admin-ops.js`, `sk106-bot.test.js`, `sk106-bot-admin.test.js` и заменить `app.js`, `server.js`, `schema.sql`, `telegram.js`, `setup-webhook.js`, `generations.js`, `.env.example`.
3. Дождаться Railway SUCCESS, проверить запуск SQL и webhook.
4. Задать BOT_ADMIN_IDS через Railway Variables отдельно, не коммитить.
5. Начать тестировать бот без оплаты генераций.
6. Netlify SK-105 НЕ требуется публиковать одновременно: изменена только серверная часть.
7. Откат: восстановить предыдущий коммит GitHub SK-101. Новые таблицы можно оставить (они аддитивные).
