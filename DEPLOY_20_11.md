# SkinCar — развёртывание SK-085 (20.11.2026)

## Назначение
Обновление исправляет загрузку фото/сохранение автомобиля, подтверждение результата при потерянном HTTP-ответе и UX формы. Архив содержит **полный репозиторий сервера**, а не патч. Текущие платежи, авторизация, каталог дисков и данные PostgreSQL должны сохраняться.

## Порядок
1. Сделать резервную копию PostgreSQL и зафиксировать текущий коммит GitHub.
2. Распаковать `SkinCar_20-11_GITHUB_RAILWAY_FULL.zip`, разместить **содержимое** ZIP в корне текущего репозитория `777svv10/skincar-server` с сохранением структуры. Не загружать ZIP одним файлом и не удалять существующую историю Git.
3. Проверить `film-packs/index.json`, `.gitignore`, `.env.example`, `wheels.json`, `wheel-references.tar.gz`, новые `upload-status.js` и `sk085-upload-status.test.js`.
4. Дождаться Railway deploy, убедиться в статусе SUCCESS, получить ответ `/health`, посмотреть `deploy` и `http` логи.
5. Лишь после этого вручную обновить Netlify через ZIP из отдельного архива. У фронтенда есть новый запрос GET `/api/uploads/status`, поэтому Netlify **не публиковать раньше Railway**.
6. Проверить Telegram Mini App на iPhone, выбрать фото 5–10 МБ, сохранить, выйти в Гараж, повторно открыть авто, сменить параметры и убедиться в работе черновика. Проверить результат генерации после обновления.

## Изменения backend
- `app.js`: GET `/api/uploads/status?vehicleId=<uuid>&photoId=<uuid>` после проверки Bearer-сессии; только подтверждение записи пользователя с согласием на данное фото.
- `upload-status.js`: независимая проверяемая функция для подтверждения состоявшейся загрузки, не возвращает сами байты фотографии.
- `sk085-upload-status.test.js`: 5 тестов на защиту от чужого доступа, отсутствие фото и отсутствие согласия.
- База: **никаких новых таблиц и миграций** в SK-085; используется текущая схема.

## Окружение и ограничения
- Токены и секреты: только в переменных Railway, никогда не добавлять `.env` в репозиторий.
- Загрузка в production из этого чата **не выполнялась**; пакет подготовлен для публикации.
- Проверить совместимость на реальной БД и реальном iPhone после развёртывания.
- Отмена/повтор при сетевом сбое безопаснее благодаря стабильному идентификатору исходного фото и проверке результата. Проблемы сети полностью исключить нельзя.
