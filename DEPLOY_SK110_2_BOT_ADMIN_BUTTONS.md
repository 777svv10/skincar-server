# SkinCar SK-110.2 — кнопочная админка Telegram-бота

**Дата:** 23.11.2026. **База:** SK-110.1 (`31b846a`).

## Доступ и безопасность

- Кнопка «🔒 Админка» в пользовательском меню появляется только для Telegram ID из `BOT_ADMIN_IDS` (два разрешённых администратора в одной переменной через запятую).
- Каждый callback, включая угадывание `a:*`, повторно проверяет роль на сервере. Клиентский текст и инлайн-кнопка сами по себе права не предоставляют.
- Приватный чат обязательно должен совпадать с Telegram ID пользователя; группы игнорируются.
- Финансовые инструменты дополнительно зависят от `BOT_CREDIT_ADMIN_ENABLED=true` и `BOT_PROMOS_ENABLED=true`. Текущие переменные Railway не записываются в исходники.

## Восьмираздельное главное меню

1. 📊 Статистика — периоды 24 ч / 7 / 30 / 90 / 365 дней / всё время, CSV.
2. 💵 Себестоимость — оценки USD по сохранённому usage и тарифам, периоды, CSV.
3. 👥 Пользователи — общие показатели без списка персональных данных.
4. 🖼 Генерации — последние работы, модели, статистика, CSV.
5. 🎟 Промокоды — статистика, безопасный выпуск.
6. 💳 Балансы — начисление и списание генераций с подтверждением.
7. 📨 Поддержка — список открытых / отвеченных тикетов; карточка, ответ, закрытие.
8. ⚙️ Система — статус бота, лимиты, модели.

Поддерживаются старые команды `/admin`, `/stats`, `/cost`, `/tickets`, `/credit`, `/debit`, `/makepromo` и предыдущие кнопки, но основной сценарий теперь кнопочный. Отладочные команды пользователям не показываются.

## Пошаговые действия

- Админ нажимает «➕ Начислить» или «➖ Списать» → отправляет три значения: `Telegram ID, количество, причина` → видит отдельное подтверждение / отмену. Баланс без подтверждения не меняется, применяются прежние лимиты и журнал.
- Админ нажимает «➕ Создать промокод» → пишет `число генераций, максимальное число активаций, срок в днях` → получает экран подтверждения и лишь после кнопки «✅ Выпустить промокод» создаётся секретный код. Повторное подтверждение той же заявки не выпускает второй промокод.
- «📨 Поддержка» → «Обращения» → тикет → «✉️ Ответить» → следующее текстовое сообщение отправляется только выбранному пользователю; «✅ Закрыть» требует подтверждения.
- Состояние ввода живёт в PostgreSQL (`bot_admin_input_state`), истекает через 10 минут, очищается периодически. Смена раздела отменяет текущий ввод. Два админа не делят одну форму между собой.

## Деплой

Изменённые файлы `bot-service.js`, `server.js`, `schema.sql`. Новый тест `sk110-2-admin-buttons.test.js`; новый документ `DEPLOY_SK110_2_BOT_ADMIN_BUTTONS.md`.

Миграция `bot_admin_input_state` выполняется автоматически из `schema.sql` при запуске Railway, без затрагивания таблиц пользователей/генераций/платежей. Сборка Netlify SK-110 остаётся без изменений и не публикуется.

`BOT_ADMIN_IDS` и оба финансовых переключателя уже настроены на Railway; обновлять их для этого релиза не требуется.

## Ограничение

Это **SK-110.2**, а не завершённая SK-111: система пользовательских обращений со скриншотами, диагностическими requestId и анализом Railway-логов остаётся запланированной SK-111.
