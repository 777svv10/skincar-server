# SkinCar SK-091 — исправление недоступности генерации плёнок

## Проверенная причина
GitHub на коммите `2e6b542` содержал `film-packs/index.json` с `packs: []`, без трёх каталогов. Работающий Railway не мог находить референсы, поэтому Netlify блокировал создание.

## Самый простой путь — 3 файла в корень GitHub
1. Перед обновлением сохраните резервную копию БД и ветки GitHub.
2. Распакуйте `SkinCar_SK091_GITHUB_ROOT_UPLOAD_3_FILES.zip`.
3. В корне репозитория `777svv10/skincar-server` загрузите три файла: `package.json`, `prepare-film-packs.cjs`, `film-packs.bundle.tar.gz`. НЕ добавляйте сам ZIP как файл.
4. После коммита GitHub Railway автоматически получит новый деплой. Скрипт `prepare-film-packs.cjs` выполнится до запуска сервера и распакует пакеты с изображениями и индексом.
5. В Railway задайте `FILM_GENERATION_MODE=public_beta`. Переменная `FILM_APPROVED_SKUS` должна отсутствовать или быть пустой, если тестируются все 151 SKU.
6. В логах нового деплоя найдите `SK091 film references ready: 151 models, 306 files` или `SK091 film references ready (cached): 151`.
7. После этого обновите Telegram Mini App и проверьте, что выбранная плёнка разблокировалась.

**Важно:** В GitHub дерево `film-packs` при таком способе может остаться пустым. Это нормально: полный каталог хранится в проверяемом `film-packs.bundle.tar.gz`, а сервер автоматически распаковывает его в своём файловом пространстве.

## Если у вас есть ПК
Можно вместо трёхфайлового способа полностью распаковать `SkinCar_SK091_GITHUB_RAILWAY_FULL.zip` и загрузить все вложенные каталоги. Скрипт всё равно проверит и восстановит каталог при запуске.

## Netlify
В этом обновлении фронтенд не менялся. Полный Netlify ZIP приложен согласно правилам проекта. Повторно публиковать его не обязательно.

## Проверки
После серверного деплоя: `/health`, наличие в логах SK091, доступность всех 151 SKU, генерация Standard, затем HD и комбинации с дисками.
