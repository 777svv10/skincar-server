# SkinCar SK-080: обход суточного лимита только для тестового Telegram ID

Текущая версия SkinCar для проверки: SK-072 на GitHub/Railway.

## Файлы
- `generations.js` — полная замена одноимённого файла в корне `777svv10/skincar-server` на ветке `main`.
- `sk080-daily-quota.test.js` — локальные проверки точного совпадения ID и сохранения существующих ограничений.

## Что изменено
Был серверный лимит 10 запусков за скользящие 24 часа для каждого пользователя. Теперь для Telegram ID из переменной `SKINCAR_DAILY_LIMIT_EXEMPT_TELEGRAM_IDS` эта проверка пропускается. Для остальных пользователей лимит сохраняется.

Важно: одно активное задание, списание кредита, общая очередь, лимит на 100 образов пользователя, глобальный лимит 200 образов, авторизация и идемпотентность не меняются. **Платные вызовы OpenAI не становятся бесплатными.**

## Публикация
1. В Railway `skincar-server` → Variables: `SKINCAR_DAILY_LIMIT_EXEMPT_TELEGRAM_IDS=306179287`. Если переменная уже задана, её не требуется создавать заново.
2. Заменить **только** `generations.js` в существующем репозитории GitHub `777svv10/skincar-server`, ветка `main`. Другие файлы не удалять и не перезаписывать.
3. Дождаться автодеплоя Railway и `SUCCESS`, проверить `/health`.
4. Открыть Mini App заново, проверить, что новый запуск проходит после ранее достигнутого суточного лимита (при наличии кредита и свободного лимита очереди).

**Важно:** переменная Railway без нового `generations.js` не отключит лимит: старая версия сервера её не использует. Netlify обновлять не требуется.

Откат: убрать ID из переменной/удалить её и развернуть сервер заново; прежний JS с жёстким лимитом тоже остаётся как резервная сборка.
